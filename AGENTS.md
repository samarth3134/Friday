# Project working instructions

- Read README.md before exploring or changing this project. It contains the architecture, setup, known gaps, acceptance checklist, and change history.
- Verify relevant source before relying on documented behavior.
- Whenever code, configuration, dependencies, setup, or important project decisions change, update the relevant README sections in the same task.
- Keep the function/test checklist current. Check items only after actual verification and record test results, remaining limitations, and unfinished next steps.
- Append a concise dated change-log entry for meaningful changes. Remove or revise known gaps when resolved.
- For read-only work, update documentation when new findings materially change project context; avoid entries for routine rereading.
- Never include keys, OAuth tokens, private messages, or stored conversation contents in documentation.
- Distinguish source inspection from runtime verification. Do not launch the assistant or trigger desktop/external actions merely to inspect the project.
